The business question

How many cases appear in main enrolment, fuzzy matching and verification exports? Which low-score cases need follow-up, and where do quality flags or statuses need reconciliation?

A record in a verification queue is not automatically a completed verification. Overlapping exports must not be added together.

The data model

locations stores the geography. case_registry stores one stable case identity. enrolments, fuzzy_matches and verification_queue each retain their source population.

Primary and foreign keys protect joins. Score checks reject values outside 0–100. Five indexes support status, score, year and location lookups.

What this demonstrates

  • Normalization and source-specific metric definitions

  • CTEs, conditional aggregation and ranking with ties
  • Missing-value handling and guarded percentage calculations

Validation and limits

SQLite execution, integrity, foreign keys, score ranges and duplicate rejection passed. The other three dialects have not been run against native servers here.
